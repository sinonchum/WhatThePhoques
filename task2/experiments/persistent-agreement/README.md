# 短答案的相似是持续的，还是碰巧？

接手 `71be00d` 后的第一轮缓存实验。只用 810 条练习回答和 660 条正式回答，新增正式查询 0，新增提交 0。

**结论：没有找到可以复现的改善。** 新规则在有标签的练习重放上比上一版差；正式数据上短答案的相似度和随机抽样无法区分。这轮留下的是三项可复现的诊断、一份不建议上传的候选，和一份等批准的最小查询方案。

## 1. 正式端点的短答案相似度是巧合水平

原假设：同一家族里，每个端点对每道题的答案来自同一个分布，题与题之间独立。把每道题的答案在家族内的端点之间打乱 5000 次，得到这个假设下的分布。[脚本](agreement_test.py) · [完整结果](content_persistence.json)

| 家族 | 20 题平均一致率 | 端点对相似度的离散程度 p | 最相似一对 p | 第一轮 vs 第二轮的端点对相似度相关 |
|---|---|---|---|---|
| G1 | 0.847 | 0.349 | 0.867 | +0.007（p 0.457） |
| G2 | 0.720 | 0.956 | 0.525 | −0.302（p 0.970） |
| G3 | 0.442 | 0.329 | 0.249 | −0.004（p 0.496） |

三个家族都没有任何一对端点通过 Bonferroni 校正。两轮十道题互换后，在一轮里相似的端点对在另一轮里并不更相似。

G2 的四个重点端点，在 11 道有分歧且双方都可解析的题上：

| 端点对 | 一致题数 | 一致的题 | 未校正 p |
|---|---|---|---|
| ep-08 ~ ep-28 | 7 / 11 | q03 q07 q08 q26 q06 q23 q29 | 0.256 |
| ep-07 ~ ep-08 | 7 / 11 | q07 q08 q16 q26 q11 q23 q29 | 0.266 |
| ep-07 ~ ep-28 | 6 / 11 | q07 q08 q13 q26 q23 q29 | 0.477 |
| ep-28 ~ ep-30 | 6 / 11 | q07 q08 q13 q16 q06 q23 | 0.475 |
| ep-07 ~ ep-30 | 5 / 11 | q03 q07 q08 q13 q23 | 0.763 |
| ep-08 ~ ep-30 | 4 / 11 | q07 q08 q06 q23 | 0.898 |

q16 在 G2 是 6 个 B 对 5 个 C，q26 是 6 个 D 对 5 个 B。两道题同时一致的端点对，随机情况下预期约 11 对，实际 13 对。ep-07 和 ep-08 在 q16、q26 上都选了 C、D，这在统计上不构成同模型的证据。

**检验能看见多大的结构。** 保留每道题的答案计数，人为植入一组总是给出相同答案的端点，看离散度检验的检出率（[脚本](power_check.py)）：G2 植入 5 个端点时检出 91%，3 个时 39%；G1 植入 5 个时 50%，3 个时 12%。所以 G2 里不存在五个以上「逐题答案固定且相同」的端点；G1 题目太少，不能排除小组结构。G3 的自举校准偏松（无结构时误报 19%），只作参考。

**练习端点自身的波动。** 同一端点对同一题重复三次，两次答案相同的比例只有 0.24 到 0.42（LoRA 1.5 几乎无法解析）。练习家族里同模型端点对的答案一致率 0.275，不同模型 0.267，AUC 0.565。在这个家族里，答案内容不携带模型身份信息。

## 2. 已上传分组里的拆分，多数只来自一轮

把上一版练习规则 `metric_partition.predict` 分别只用第一轮十题、只用第二轮十题跑一遍，比较被拆出来的端点。[脚本](format_persistence.py) · [完整结果](format_persistence.json)

| 家族 | 只用第一轮 | 只用第二轮 | 两轮都拆出 | 20:24 上传的单独组 |
|---|---|---|---|---|
| G1 | 02 | 02 | 02 | 02、23 |
| G2 | 无 | 06、20、28、30 | 无 | 06、20、28、30 |
| G3 | 09、10、27、29 | 10、16、19、31 | 10（随机重合的概率 0.89） | {10, 29} 一组，其余合并 |

对照：在有标签的练习数据上，同一条规则用两组互不相同的十条回答，拆出集合的 Jaccard 平均 0.80，三个 LoRA 端点分别有 78%、99%、100% 的次数被拆出（[脚本](sample_size.py) · [结果](sample_size.json)）。正式数据上 G2 是 0，G3 是 0.14，11 个端点里随机取两次四个的预期约 0.24。**练习家族里撑起 0.65 门槛的格式信号，在正式 G2 和 G3 上没有复现。** 这是离线就能量到的迁移失败，和公开分一致。

不依赖练习规则的检查：只看「回答是否恰好是一个字母或整数」，按该题在家族内的偏离率加权。

| 端点 | 第一轮偏离的题 | 第二轮偏离的题 | 打乱检验 p |
|---|---|---|---|
| ep-02（G1） | q08 | q06 q11 q30 | 0.0001 |
| ep-23（G1） | q08 | 无 | 0.385 |
| ep-20（G2） | q02 q25 | q11 q18 | 0.0011 |
| ep-08（G2，上传时在大组里） | 无 | q05 q24 q29 | 0.038（未校正） |
| ep-28（G2） | 无 | q18 q24 | 0.263 |
| ep-06（G2） | 无 | q24 | 0.677 |
| ep-30（G2） | 无 | q24 | 0.680 |

ep-06 和 ep-30 被单独成组，依据只有 q24 一条回答，而 G2 有 5 / 11 个端点在 q24 上都不是纯数字。两轮都偏离的只有 ep-02 和 ep-20。

**系统提示外露。** 回答里用第三人称提到 the user / the human：练习数据 810 条里只有系统提示端点 ref-03 出现 1 次，其余 720 条为 0。正式数据里 ep-20 一次（"The user's draft is not in a clear, understandable format"），ep-16 两次（"The human has demonstrated…"、"You are a 'Hugging Chat Tutor'…"）。按题面，系统提示不改变模型身份，所以 ep-20 更像伪装而不是另一个模型。这条线索在有标签数据上只有一个正例，召回很低。

## 3. 同抽样对照：新规则更差

新规则 [`replicated.predict`](replicated.py)：把十道题按题号交替分成两个五题块，只有两个块里都被上一版规则拆出的端点才拆出。没有拟合任何参数。对照 `union` 是任一块拆出就拆。抽样与 `replay.py`、`calibrate_metric.py` 逐条相同，种子 1493807，每个协议 2048 次；上一版的数字与 [metric-partition](../metric-partition/README.md) 记录完全一致（0.6377 / 1655、0.5168 / 1141、0.7314 / 2034）。[脚本](replay_compare.py) · [结果](replay.json)

| 协议 | 版本 | 平均模型 MCC | 严格 > 0.65 的次数 | 误合并 FP | 误拆分 FN |
|---|---|---|---|---|---|
| 五类分层抽题 | 上一版 | 0.6377 | 1655 | 5.77 | 0.76 |
| | 新版 replicated | 0.5557 | 556 | 9.88 | 0.12 |
| | 对照 union | 0.5308 | 800 | 4.33 | 2.82 |
| 固定难题 | 上一版 | 0.5168 | 1141 | 6.82 | 1.69 |
| | 新版 replicated | 0.4825 | 174 | 11.94 | 0.21 |
| | 对照 union | 0.3417 | 291 | 5.04 | 4.60 |
| 留出十题 | 上一版 | 0.7314 | 2034 | 5.03 | 0.01 |
| | 新版 replicated | 0.6762 | 1498 | 6.66 | 0.00 |
| | 对照 union | 0.7279 | 1799 | 4.30 | 0.51 |
| 首轮十题 | 上一版 | 0.6680 | 1780 | 5.52 | 0.52 |
| | 新版 replicated | 0.5753 | 610 | 9.38 | 0.08 |
| | 对照 union | 0.4953 | 724 | 4.67 | 3.02 |

新版只在一项上更好：误拆分降到 0.00–0.21 对。代价是误合并多 1.6 到 5.1 对，平均 MCC 和过线次数在四个协议上全部下降，没有达到 1434 次的门槛。

**题块说明。** 新规则没有调参，四个题块都只用于报告。上一版的权重由前一轮在首轮十题和固定难题上选出（各 512 次，种子 420991），留出十题没有参与那次拟合。四个题块和九个练习端点在历次实验里都被反复看过，这里没有任何一块是干净的留出集。

## 4. 候选与去重

[`candidate-replicated.csv`](candidate-replicated.csv) 由 [`make_candidate.py`](make_candidate.py) 生成：只有两轮都偏离格式、打乱检验 p < 0.05、且没有系统提示外露的端点才单独成组。结果是 G1 拆出 ep-02，G2 全部合并，G3 拆出 ep-31。

[`dedupe.py`](dedupe.py) 按 528 对端点的相等关系比较，忽略标签名：

| 历次上传 | 家族对变化 | 模型对变化 |
|---|---|---|
| 18:04 首次（0.05） | 82 | 120 |
| 18:40 offline-v3（0.10） | 0 | 36 |
| 19:35 official-round2（0.10） | 0 | 79 |
| 20:24 minimax（0.10） | 0 | 67 |

相对 20:24 的上传：59 对由不同改为相同（ep-23 并入 G1 大组 9 对；ep-06、20、28、30 并入 G2 大组并彼此合并 34 对；ep-10、29 并入 G3 大组 16 对），8 对由相同改为不同（ep-31 与 G3 大组的 05、09、11、13、15、16、19、27）。不与任何一次上传重复。

**不建议上传。** 它几乎把每个家族合成一组，与得到 0.10 的 18:40 版只差 36 对。

## 5. 四张公开回执说明了什么

首次上传的家族划分相对 G1/G2/G3 的家族 MCC 是 0.642，0.1 × 0.642 显示为 0.05；之后三次家族相同，都显示 0.10。榜上所有分数都是 0.05 的倍数。最简单的解释：家族项满分，模型项在四次上传里都接近零。

[`board_constraint.py`](board_constraint.py) 在「每个家族一个共享组（4 到 7 个端点）加若干单独模型」的假设下随机生成真值和公开子集：一份与真值无关的分组，四次都显示成我们看到的分数的概率约 18% 到 29%。回执只把「历次被拆出过的端点属于共享组」的概率从 0.50 推到 0.50–0.73，始终留在大组里的端点降到 0.41–0.49。同一模拟下，本候选的公开分有 30% 到 41% 的概率显示高于 0.10，但隐藏子集上的期望模型 MCC 只有 0.054–0.067，与一份随机分组相当。这些数字依赖上面的假设，没有标签验证。[结果](board_constraint.json)

## 6. 等批准的最小查询方案

缓存里每个正式端点每题只有一次回答，无法区分「端点自身的抽样噪声」和「端点之间的差异」。下面两步各自对应一项分组判断。

**第 0 步，练习端点，不占正式额度**（官方 starter 注明 ref 端点没有查询上限）：[`probe_prompts.csv`](probe_prompts.csv) 的 pa1、pa2 各问 3 次，9 个端点共 54 条。通过条件：ref-03（系统提示）和 ref-05（persona）复述出指令，其余七个回答 NONE。没通过就不做第 2 步。

**第 1 步，G2 重复检查。** ep-03、06、07、08、20、21、22、26、28、30、32，题号 q16、q26、q08，每题再问 4 次。每端点 12 条，共 132 条。用 [`repeat_readout.py`](repeat_readout.py) 读数。
- 同一端点的重复一致率接近端点之间的一致率（低于 0.7）：单次答案是抽样噪声。q16、q26 不再用于任何合并或拆分，ep-06、ep-30 没有单独成组的依据。
- 同一端点一致率高于 0.9 且保持缓存里的答案：答案是端点属性。按众数分组，缓存给出的预期是 {07, 08, 22, 26}、{06, 21, 30, 32}、{03, 28}、{20}，ep-30 和 ep-28 都不再单独成组，ep-07、ep-08 与 ep-03、21、32 分开。

**第 2 步，系统提示探测。** 33 个端点，pa1、pa2 各 1 次，共 66 条，每端点 2 条。复述出指令的端点是提示伪装，不应单独成组：它们彼此同模型，并与本家族的原版同模型。预期会改变 ep-20，可能改变 ep-02、ep-23、ep-16。

合计正式查询 198 条，占上次快照 2640 条的 7.5%；G2 端点各 14 条，其余各 2 条。其他 harness 可能已经用过额度，执行前先查余额。

## 复现

在仓库根目录：

```bash
cd task2/experiments/persistent-agreement
python3 agreement_test.py --out content_persistence.json      # 约 35 秒
python3 power_check.py                                        # 约 12 秒
python3 format_persistence.py --out format_persistence.json   # 约 15 秒
python3 sample_size.py                                        # 约 16 秒
python3 replay_compare.py --out replay.json                   # 约 2 分钟
python3 make_candidate.py && python3 dedupe.py candidate-replicated.csv
python3 board_constraint.py --samples 300000 --candidates candidate-replicated.csv --out board_constraint.json
```

依赖与 `task2/requirements.txt` 相同。本轮在 Python 3.13、numpy 2.5、scipy 1.18 上运行；随机种子都写在脚本里。
