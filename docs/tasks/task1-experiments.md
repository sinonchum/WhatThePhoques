# Task 1：第一轮定位实验

目标：在同一份留出集上对比“已知消息提供的定位信号”和“不看消息的基线”，先取得可复现的逐方法分数，再决定如何用 GPU。尚未运行模型，以下没有排行榜成绩。

## 已核实

- [官方 starter kit 与训练集（固定版本）](https://huggingface.co/datasets/SprintML/Hackathon_Watermark_Localisation_Task_Paris/tree/8d27b2c9cc37c4829c8501e43e11fcb1b5db58c0)。检查了 `wmloc/watermarks.py`、`data.py`、`utils.py` 和 `submission_template.py`。
- 从 `train.zip` 读取 `metadata.json` 和 `masks_128.npz`，按 `image_name` 关联。510 张、每种方法 170 张。按官方逐图两类 mIoU 定义，全 0 得 **0.2518**，全 1 得 **0.2482**（全训练集参照值，不是留出成绩）。水印面积占比的第 10、50、90 百分位约为 **1.3%、47.3%、98.2%**。局部小水印和几乎整图都有水印的情况都必须测。
- 每种方法的 `full_watermark` 恰好 85 真、85 假。这是**训练专用**字段，不能输入预测器或用来选择测试时的分支。测试可用 `method` 和 `message`。

## 实验顺序

1. **锁定比较标准。** 按 `method × full_watermark` 分层；如发现近重复原图，整组留在同一侧。固定随机种子、保存图名清单，约 80% 用于开发，约 20% 留出。阈值只在开发部分选择。在同一留出集上比较全 0、全 1、按方法统计训练掩码得到的空间先验，以及以下预测器。用 `wmloc.utils.score` 按图算两类 IoU，再报总体、逐方法和小面积/大面积样本分数，不把整批像素拼在一起打分。
2. **PixelSeal / TrustMark：用已知消息投票。** 实际封装都返回 `features(x)['per_position_logits']`。对消息第 `k` 位 `b[k]`，把对应空间通道乘以 `2*b[k]-1`，再对所有位取均值，得到与正确消息一致的热图（先把 `uint8` 转成浮点，避免负号溢出）。上采样到 128×128，两种方法各自在开发集校准阈值。做固定种子的乱序消息对照，判断提升来自消息还是位置偏差。不要把整图解码接近随机直接当成全黑掩码。
3. **StegaStamp：先做小规模遮挡对照。** 该封装的 `features()` 默认只有整图 100 位 logits，没有上述空间图。先在开发集选不同水印面积的样本，用 4×4、8×8 两种网格逐块模糊，记录正确消息的带符号平均 logit 比原图下降多少，形成粗热图。对照错误消息、记录每图耗时和 mIoU。遮挡也可能破坏解码器对齐，若定位不优于空间先验，不扩到全量，改试 RGB 高频残差加轻量分割头，直接用 `mask128` 监督。
4. **按错误类型升级。** 先看小物体漏检、细条断裂和大水印内部的洞，再决定是否融合浅层特征或细化边缘。保留不做后处理的对照，不把所有预测强行拟合为矩形。最终导出 `[1020,128,128]` 的 `uint8`/`bool` 二值张量，图名无扩展名且与测试集严格一一对应。PDF 写 20 MB，starter README 写 25 MB，以更严格的 **20 MB** 为准；保持模板 `SUBMIT=False` 直到决定正式提交。

第一轮交付：固定划分、三类方法的留出 mIoU、正确/错误消息对照、每图耗时，以及每种方法至少一张原图/真值/预测对照。先验证定位，再花时间训练。
